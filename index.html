快問快答 9 題

Q1 · 填空 · WHERE

找出租金 0.99 的影片：SELECT title FROM film ____ rental_rate = 0.99;

看答案

WHERE。篩選資料列用 WHERE。

Q2 · 選一個 · SUM 還是 COUNT

「每位顧客付了多少錢」要用 COUNT(amount) 還是 SUM(amount)？

看答案

SUM(amount)。COUNT 數的是筆數，SUM 才是金額加總。

Q3 · WHERE 還是 HAVING

要找「付款超過 10 次的顧客」，條件 COUNT(*) > 10 要寫在哪裡？

看答案

HAVING。WHERE 在分組前執行，那時還沒有 COUNT 的結果。

Q4 · 找錯 · JOIN

JOIN category AS c ON fc.film_id = c.category_id 哪裡錯？

看答案

兩邊意義不同。JOIN 要接表示同一件事的欄位：fc.category_id = c.category_id。

Q5 · 找錯 · NULL

WHERE return_date = NULL 為什麼一筆都查不到？

看答案

NULL 不能用等號比較，要寫 IS NULL。

Q6 · 排序

「最近的 10 筆租借」和「最便宜的 10 部電影」各要用 ASC 還是 DESC？

看答案

最近 = 日期最大，ORDER BY rental_date DESC LIMIT 10；最便宜 = 由小到大，ORDER BY rental_rate ASC LIMIT 10。

Q7 · 寫出來 · CONCAT

要輸出 SMITH, MARY 這種格式，CONCAT 怎麼寫？

看答案

CONCAT(last_name, ', ', first_name)，逗號後面有一個空白。

Q8 · 找錯 · GROUP BY

GROUP BY c.first_name 統計每位顧客的付款次數，會出什麼問題？

看答案

名字相同的不同顧客會被併成一組。分組要用 c.customer_id。

Q9 · 執行順序

SELECT COUNT(*) AS 次數 … ORDER BY 次數 可以嗎？那 WHERE 次數 > 5 呢？

看答案

ORDER BY 可以用別名，它在 SELECT 之後執行；WHERE 不行，它在 SELECT 之前就執行了，要改寫成 HAVING COUNT(*) > 5。

新觀念 1：日期範圍 18:45–18:55

sakila 裡的 rental_date、payment_date、return_date 都是 DATETIME，除了日期還帶有時分秒，例如 2005-07-06 14:23:05。

例子：查 2005/7/5 到 2005/7/6 這兩天的所有付款。直覺會寫成 BETWEEN '2005-07-05' AND '2005-07-06'，結果卻少了資料。

07-05 00:0007-06 00:0007-07 00:00
寫法 A：BETWEEN '2005-07-05' AND '2005-07-06'
只到 07-06 00:00:00
寫法 B：>= '2005-07-05' AND < '2005-07-07'
包含 7/6 整天
陷阱　只寫日期的 '2005-07-06' 和 DATETIME 比較時，會被當成 2005-07-06 00:00:00。所以寫法 A 只算到 7/6 凌晨 0 點整，7/6 當天其他時間的資料全部漏掉。

三種安全寫法

-- 1. 半開區間（推薦）：結束日期 +1 天，用「小於」
WHERE payment_date >= '2005-07-05' AND payment_date < '2005-07-07'

-- 2. 先取出日期部分再比較
WHERE DATE(payment_date) BETWEEN '2005-07-05' AND '2005-07-06'

-- 3. 把結束時間寫到最後一秒
WHERE payment_date BETWEEN '2005-07-05 00:00:00' AND '2005-07-06 23:59:59'
延伸：YEAR()、MONTH()、DAY() 可以單獨取出年、月、日，例如 WHERE YEAR(payment_date) = 2005 AND MONTH(payment_date) = 7。

學校有 3 個社團，但「程式設計社」剛成立，還沒有學生加入：

社團博覽會要列出「每個社團有幾位成員」，程式設計社雖然 0 人也要出現。Day12 用的 JOIN（INNER JOIN）只保留兩邊都配對成功的資料，程式設計社配不到任何學生，整列消失。LEFT JOIN 則會保留左表的每一列，配不到的部分補 NULL。

club JOIN student

程式設計社不見了。

club LEFT JOIN student
社團學生
吉他社小明
吉他社小美
熱舞社小華
程式設計社NULL

程式設計社留下來，學生欄位是 NULL。

SELECT 欄位
FROM 一定要全部列出的表 AS a          -- 左表
LEFT JOIN 可能配不到的表 AS b         -- 右表
       ON b.a_id = a.a_id;

每個社團有幾位成員？COUNT(*) 還是 COUNT(欄位)？

社團LEFT JOIN 後的列COUNT(*)COUNT(s.id)
吉他社2 列22
熱舞社1 列11
程式設計社1 列（s.id 是 NULL）1 ✗0 ✓
 
SELECT c.name AS 社團, COUNT(s.id) AS 成員數
FROM club AS c
LEFT JOIN student AS s ON s.club_id = c.id
GROUP BY c.id, c.name;
陷阱　COUNT(*) 數的是「列數」，LEFT JOIN 補出來的那一列也算 1，程式設計社會變成 1 人。要數「有幾位成員」得用 COUNT(右表的欄位)，COUNT 遇到 NULL 不會計入。
左右順序很重要：「所有社團都要列出」→ club 放左邊。寫成 student LEFT JOIN club 的話，保留的是所有學生，程式設計社照樣不見。
延伸：用 LEFT JOIN 找「沒有配對」的資料

LEFT JOIN 之後加 WHERE 右表.主鍵 IS NULL，留下的就是「左表有、右表沒有」的資料，例如還沒有人加入的社團：

SELECT c.name
FROM club AS c
LEFT JOIN student AS s ON s.club_id = c.id
WHERE s.id IS NULL;   -- 結果：程式設計社

新觀念 3：COUNT(DISTINCT) 與前 N 名 19:10–19:20

COUNT(DISTINCT)：重複的只算一次

例子：有多少位顧客付過款？一位顧客會付很多次款，所以 payment 表裡同一個 customer_id 會出現很多次。

✗ 數到的是付款筆數
SELECT COUNT(customer_id)
FROM payment;
✓ 去除重複再數
SELECT COUNT(DISTINCT customer_id)
FROM payment;
寫法數的是
COUNT(*)列數（含 NULL 的列）
COUNT(欄位)該欄位不是 NULL 的列數
COUNT(DISTINCT 欄位)該欄位有幾種不同的值

前 N 名：同分怎麼辦？

例子：庫存份數最多的前 3 部電影。假設分組計數後是這樣：

片名庫存數
ACADEMY DINOSAUR8一定是第 1 名
BUCKET BROTHERHOOD7三部都是 7，只剩 2 個名額
APACHE DIVINE7
CURTAIN VIDEOTAPE7

表中數字是教學用的假設值。

只寫 ORDER BY 庫存數 DESC LIMIT 3 的話，同分的三部誰排前面由資料庫決定，每次結果可能不同。題目通常會指定第二排序鍵，例如「同分再依片名遞增」：

SELECT f.title AS 片名, COUNT(*) AS 庫存數
FROM inventory AS i
JOIN film AS f ON i.film_id = f.film_id
GROUP BY f.film_id, f.title          -- 用 ID 分組，避免同名被併在一起
ORDER BY 庫存數 DESC, f.title ASC   -- 第二排序鍵處理同分
LIMIT 3;
分組要用 ID，不要只用名稱。兩位顧客可能同名同姓，用名稱分組會把兩個人的資料算成一個人。

解題流程與執行順序

寫 SQL 的順序和資料庫執行的順序不同。卡住時照執行順序想一遍：

FROM / JOIN→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT

所以 WHERE 不能用 COUNT 的結果（要用 HAVING），而 ORDER BY 可以用 SELECT 裡取的別名。

步驟問自己
1. 看輸出欄位要幾欄？順序？名字要合併嗎？分隔字元是什麼？
2. 找資料表欄位在哪幾張表？需要 JOIN 嗎？
3. JOIN 種類配不到的資料也要列出嗎？要就用 LEFT JOIN，主表放左邊
4. 條件篩資料列用 WHERE，篩群組用 HAVING；日期範圍注意時分秒
5. 分組與計數GROUP BY 用 ID；COUNT(*)、COUNT(欄位)、COUNT(DISTINCT) 選哪個？
6. 排序遞增還是遞減？同分時的第二排序鍵？要 LIMIT 嗎？

H
SELECT r.rental_id AS 租借ID,
       CONCAT(c.last_name, ' ', c.first_name) AS 租借者姓名,
       r.rental_date AS 租借時間
FROM rental AS r
JOIN customer AS c ON r.customer_id = c.customer_id

  AND r.rental_date <  '2005-06-16'

I
SELECT l.name AS 語言名稱,
       COUNT(f.film_id) AS 電影數量
FROM language AS l
LEFT JOIN film AS f ON f.language_id = l.language_id
GROUP BY l.language_id, l.name
ORDER BY 電影數量 DESC, l.name ASC;
